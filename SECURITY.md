# Security reporting

Report suspected credential exposure or access-control defects privately to the repository owner through GitHub's available private reporting channel or another owner-agreed private channel. Do not place credentials, customer data or exploitable production details in public issues. This repository is private, but secrets still belong in environment variables rather than source control.

Do not merge production authentication, payment, refund or inventory changes without permission and concurrency checks. Test against isolated data. Follow the operational specification for rotation, incident response, redaction and recovery. A supported contact address and reporting policy must be configured before public launch.
